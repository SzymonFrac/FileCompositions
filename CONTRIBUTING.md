## Questions & Discussions

If you have:

- **Feature suggestions**
- **Questions about the project**
- **Built with File Compositions and want to share**

Open a [Discussions](../../discussions) tab rather than an issue.
\
If a discussion leads to a concrete task, it can be converted to an issue.


## What help is File Compositions looking for?

File Compositions always benefits from common but important contributions, including:

- **Bug reports** - Found something broken? Open an issue with reproduction steps
- **Documentation and Examples** - Clearer docs with examples always help

### Code related contributions

Code contributions are welcome; however, there are limited resources on the source code.
I recommend waiting for complete or partial guides on navigating the source code.

Although, if you still want to contribute code then open an issue about your change.
This helps to confirm whether the change aligns with the project's direction, before any code is written.
I will explain whether the change is feasable, and explain the source code if necessary.

Detailed contributor documentation (architecture overview, build instructions, code conventions) may be added as the project grows.

In the future, the most wanted contributions will be to support different file types.
File Compositions aims to support as many file types as possible, which is a big task.
A guide for implementing different files types will likley be one of the first.
